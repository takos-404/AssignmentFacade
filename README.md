Flight Reservation System (Assignment 4)

Простая система бронирования авиабилетов, демонстрирующая работу паттерна Facade и компенсирующих транзакций (Saga).

🚀 Как запустить проект (Live Demo)

Откройте проект в вашей IDE (IntelliJ IDEA / Eclipse).

Запустите класс Main.java.

В консоли появится интерактивное меню:

Опция 1: Успешная покупка билета (Шаги A -> B -> C проходят успешно).

Опция 2: Сбой на Шаге B (Багаж тяжелее 20 кг). Показывает откат (rollback) Шага A.

Опция 3: Сбой на Шаге C (Аккаунт заблокирован). Показывает откат Шагов B, а затем A.

Опция 4: Показать состояние базы данных (полезно для проверки статусов).

Опция 5: Очистить базу данных.

💾 База данных (Persistence)

Вместо сложных SQL-баз, данные сохраняются в простые текстовые файлы (формат CSV). Это позволяет данным переживать перезапуск приложения:

A_reservations.txt - Данные о местах.

B_tickets.txt - Данные о билетах.

C_loyalty.txt - Начисление миль.

Chain_states.txt - Сохраняет текущий прогресс транзакции на случай непредвиденного отключения (света или интернета).

🛡️ Principle of Least Knowledge (До и После)

ДО (Без Фасада - Плохо):
Клиентский код (Main) знает слишком много. Ему приходится вручную дергать все базы и самому писать логику отмены, если что-то пойдет не так.

// Клиент сам создает бронь, сам проверяет багаж, сам откатывает ошибки...
SeatReservation res = new SeatReservation(txId, seat, price, ReservationStatus.HELD);
repoA.save(res);
try {
    baggageEngine.validate(weight);
    ETicket ticket = ticketIssuer.issue(txId);
    repoB.save(ticket);
} catch (BaggageException e) {
    // Вручную пишем откат
    res.status = ReservationStatus.RELEASED; 
    repoA.save(res); 
}


ПОСЛЕ (С Фасадом - Хорошо):
Клиент общается только с одной "кнопкой" — Фасадом. Он не знает, как устроены подсистемы внутри. Вся сложная логика откатов спрятана.

// Клиент знает только об одном классе - Фасаде.
ClientBookingFacade facade = new ClientBookingFacade();
facade.bookFlight("A12", 15.0, "USER_99"); 


🤔 Рефлексия: Facade vs Adapter

Почему здесь нужен именно Фасад, а не Адаптер?

Всё просто. Адаптер — это переходник. Мы используем его, когда у нас есть два несовместимых куска кода, и нам нужно заставить их работать вместе (как переходник для европейской розетки под американскую вилку). Мы не пытаемся изменить интерфейс одной подсистемы под другую.

Фасад — это пульт от умного дома. У нас есть три совершенно разные, независимые системы (бронирование мест, выдача билетов и программа лояльности). Фасад нужен для того, чтобы скрыть эту сложную композицию и алгоритм откатов за одним простым методом bookFlight(). Клиенту не нужно нажимать три разные кнопки, он нажимает одну, а Фасад делает всю грязную работу под капотом.
